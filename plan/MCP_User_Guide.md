# rz-mcp 使用说明（兼验收清单）

> 2026-11-26。本文描述的是改造**完成后**的用法，目前只有第 3 节（文档查阅）可用。
> 设计依据见 [MCP_Rebuild_Plan.md](MCP_Rebuild_Plan.md)。服务器名 `rz-dev` 是暂定名。
> 本文同时是验收清单：每个场景都有编号和通过标准，第 9 节汇总。工具的参数名在工作包 P1 定稿，本文里的写法是示意。

## 1. 怎么用：一句话

**你不需要记工具名，也不需要输入任何命令。** 在任意目录下打开 Claude Code，用自然语言说你要做什么，agent 会自己选择并调用工具。你只在两种时候需要动手：

- agent 转告你一句物理操作，例如"把 SW_MODE 拨到 OFF ON OFF，然后上电"。你照做即可，**不用回复**，工具会从串口看到板子的反应并继续。
- 跑完整 PoC 时，确认一次设计文档。

## 2. 一次性准备

在那台 Linux 主机上各做一次。

| 步骤 | 做什么 | 备注 |
|---|---|---|
| 1 | 建文档库：把资料放进 `docs/`，运行 `python -m rzmcp.build` | 约 16 秒 |
| 2 | 填写 `config.toml`：Yocto 项目目录、容器名、串口、USB 网卡、TFTP 目录、PoC 根目录、授权软件包目录 | 机器相关的值只在这一处 |
| 3 | 运行主机配置脚本（需要 sudo）：串口权限、USB 网卡固定 IP、DHCP 和 TFTP | 只为上板功能；不做也能用文档和构建 |
| 4 | 启动服务器（systemd 用户服务，常驻） | |
| 5 | 在 Claude Code 里添加服务器：`claude mcp add --scope user --transport http rz-dev http://localhost:8765/mcp --header "Authorization: Bearer <token>"` | `--scope user` 让所有目录下的会话都能用 |
| 6 | （可选）在 Claude Code 的设置里允许本服务器的工具，免去每次写板和构建时的确认弹窗 | 不配置也能用，只是多点几次确认 |
| 7 | 接线：USB-C 电源、"UART Debug" micro-USB、USB 网卡接板子任意一个 RJ45 口 | |

**验收 A0**：完成以上步骤后，在一个无关的空目录下新开会话，问"rz-dev 能做什么"，agent 能说出文档查阅、Yocto、PoC、上板四类能力。

## 3. 查资料

| 编号 | 你说 | 会发生什么 | 通过标准 |
|---|---|---|---|
| D1 | "WDTSET_2 寄存器的地址和位域是什么" | 调用 `lookup_register` | 给出地址、复位值、位域，并注明 doc_id、Rev、页码 |
| D2 | "RZ/G3L 的启动模式引脚怎么设置" | `search_docs`，再用 `get_section` 或 `read_pages` 读原文 | 回答引用了原文页码，不是只凭检索片段 |
| D3 | 问一个尚未结构化的模块的寄存器 | `lookup_register` 如实返回"没有"，agent 转用 `search_docs` | 不凭记忆编造数值 |
| D4 | "PM4 的 function 5 是什么，能和哪些引脚一起用" | `search_docs`，命中引脚功能表 `LLWEB-20218308-02` 的 PM4_AWO 记录（整条显示） | 答出 RSCI0_RXD_MISO_SCL，并说明红框组合 PM5–PM7；引用 doc_id 和引脚名 |

## 4. 上板（可以完全单独使用）

这一组不需要存在任何 PoC 或 Yocto 项目。你手上有一个镜像文件就可以用。

### 4.1 看板子现在什么状态

- **你说**："板子现在能用吗" / "EVK 是什么状态"
- **会发生什么**：调用 `board_status`。它检查主机（串口、网卡、TFTP）和板子（没反应、BootROM、Flash Writer、U-Boot、Linux），不写任何东西。
- **验收 B1**：主机配置缺一项时，回答里有补上它的确切命令；板子的状态判断与实际一致。

### 4.2 把一个镜像文件写进板子

- **你说**："把 `/path/to/xxx.wic.gz` 写进 EVK 的 eMMC"（或"……写进 QSPI"，或"只换 rootfs"）
- **会发生什么**：
  1. 调用 `board_flash`，立即返回作业号，以及**这次一共需要你做哪几次物理操作**。
  2. agent 用 `job_status` 跟进度，隔一段时间向你报告一次。
  3. 需要你动手时，agent 把操作说明原样转告你。你做完不用回复。
  4. 写完自动读回校验，启动到 `login:`，给出报告：写了什么、写到哪里、校验和、各组件版本、耗时。

- **你要准备的文件**：

  | 写什么 | 需要的文件 |
  |---|---|
  | 只写 rootfs | 一个 `.wic.gz` |
  | 写 bootloader（或全部） | 另需 BL2、FIP、Flash Writer。放在镜像同一目录下会自动找到，也可以在请求里逐个给出路径 |

- **你要做的物理操作**：

  | 板子的起始状态 | 你的操作 |
  |---|---|
  | 能启动到 U-Boot，只换 rootfs | 无（最多按一次 RESET） |
  | 能启动到 U-Boot，换 bootloader | 目标是无；取决于计划里的调研项 S1，不可行时为 2 次 |
  | 空板，或 bootloader 已损坏 | 2 次：拨到 SCIF 下载模式并上电；拨到目标启动模式并复位 |

- **验收**：

  | 编号 | 场景 | 通过标准 |
  |---|---|---|
  | B2 | 空板 → eMMC 启动 | 在无关目录的新会话里只说一句话，到 `login:`；连续 3 次成功；每次你的操作 ≤ 2 次，且没有键盘应答 |
  | B3 | 空板 → QSPI 启动 | 同上 |
  | B4 | 只换 rootfs | 连续 3 次成功；你的操作 0 次 |
  | B5 | 缺文件或文件不对 | 在碰板子之前报错，并列出缺什么 |
  | B6 | 中途出错（拔网线、取消作业） | 给出明确的原因和下一步；再说一次同样的话能接着做完，不要求你重复已做过的物理操作 |
  | B7 | 串口被别的程序占用，或已有上板作业在跑 | 直接说明被谁占用，不会卡住 |

### 4.3 在板子上执行命令

- **你说**："在 U-Boot 里执行 `mmc info`" / "看一下板子上的 `dmesg | grep wdt`"
- **会发生什么**：调用 `board_exec`，返回命令输出。
- **验收 B8**：U-Boot 和 Linux 两种位置都能执行并返回完整输出；板子不在对应状态时，说明当前状态和该怎么做。

### 4.4 按一份验证计划做验证

- **你说**："按 `/path/to/verify.toml` 在板子上验证"
- **会发生什么**：调用 `board_verify`。逐项执行（板子的 Linux、主机、启动过程计时），按计划里写明的判据判定，生成验证报告和原始日志。
- **验收 B9**：不存在 PoC 时也能执行；报告逐项列出通过或不通过及依据；有不通过项时不会报成整体通过。

## 5. Yocto 环境和构建（可以单独使用）

| 编号 | 你说 | 会发生什么 | 通过标准 |
|---|---|---|---|
| Y1 | "RZ/G3L 的 Yocto 环境搭好了吗" | `yocto_status` | 说明项目是否可用、装了哪些可选组件、有没有构建在跑、源码和产物在哪 |
| Y2 | "给 RZ/G3L 搭一个 Yocto 环境"（可加"带图形包"） | `yocto_setup`，作业 | 空目录上搭出可用项目；已可用时直接复用，只补缺的部分；中断后再说一次能接着做 |
| Y3 | "构建官方镜像" | `poc_build`，不带 PoC | 构建出官方镜像，返回镜像路径；失败时返回出错的任务和日志位置 |
| Y4 | 已有构建在跑时再要求构建 | 拒绝并说明哪个作业在跑 | 不会并发启动两个 bitbake |

授权软件包（graphics、codecs、security）要你先从 renesas.com 下载，放进 `config.toml` 指定的目录。缺包时 `yocto_setup` 会说明缺哪个文件。

## 6. 完整的 PoC

- **你说**："我想做一个 PoC：<你的设想>"
- **会发生什么**：

  | 步 | agent 做什么 | 你做什么 |
  |---|---|---|
  | 0 | 检查 Yocto 环境，没有就搭 | — |
  | 1 | 创建 PoC 仓库；查文档、读源码；写设计文档和上板验证计划 | — |
  | 2 | 把设计交给你 | **确认设计**（可以提修改意见） |
  | 3 | 写代码、构建；构建失败自己修 | — |
  | 4 | 写板、按验证计划验证；不通过就回到第 3 步 | 按提示拨码、上下电 |
  | 5 | 写文档，生成交付包 | — |

- **交付包里有什么**：`layers/`、`docs/`（md 和 pdf）、`image/`、README、版本清单、校验和。
- **换个会话接着做**：任何时候在任意目录下新开会话，说"继续 <PoC 名称>"。agent 调用 `poc_status` 就知道做到哪一步、下一步是什么。
- **验收**：

  | 编号 | 场景 | 通过标准 |
  |---|---|---|
  | P1 | 从设想到交付包 | 在无关目录的新会话里只说设想，走到交付包；你的介入只有一次设计确认和物理操作，其他任何介入都记为缺陷 |
  | P2 | 中途换会话 | 在第 3、4、5 步各换一次新会话，都能凭 `poc_status` 接着做 |
  | P3 | 问进度 | "<PoC 名称> 做到哪了"得到当前步骤、上一步的结果和下一步 |
  | P4 | 交付包 | 结构符合上面的清单；不含授权软件包和设计过程文件 |

## 7. 长任务怎么跟

搭环境、构建、写板、验证都是作业，共用一套方式。

| 你说 | 会发生什么 |
|---|---|
| "现在进度怎么样" | `job_status`：当前第几步、进度、是否在等你操作 |
| "停掉" | `job_cancel` |
| 关掉会话后重新打开，问"刚才的写板怎么样了" | 作业不随会话或服务器重启而中断，新会话能查到 |

**验收 J1**：写板进行中关掉会话、重启服务器，作业继续跑完；新会话能查到结果。
**验收 J2**：作业在等你操作时，agent 一定会把操作说明告诉你，不会默默等到超时。

## 8. 出问题时

| 现象 | 怎么办 |
|---|---|
| agent 没有调用工具，自己去翻文件或写脚本 | 这是缺陷，请记下你当时说的原话，它会加入识别测试 |
| agent 说找不到工具 | 运行 `claude mcp list`，确认 `rz-dev` 显示已连接 |
| 一直等不到板子反应 | 板子可能在工具开始前就上电了，按一次 RESET |
| 写板失败 | 再说一次同样的请求，工具会从板子当前状态接着做 |
| 想看完整日志 | 每个作业的目录在 `data/jobs/<作业号>/`，里面有完整日志和 `report.md` |

|---|---|---|
| 准备 | A0 | P1 |

**总的通过条件**：

1. 以上每一项都在**与本项目无关的目录下新开的会话**里验证，只用自然语言。
2. 第 3～7 节里"你说"一栏的每句话，重复 5 次，agent 至少 4 次第一步就选对工具（计划 6.1 的识别测试）。
3. 上板的 B2、B3、B4 在实机上完成，不以假板子的结果代替。
