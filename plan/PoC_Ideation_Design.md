# 自动构想 PoC：设计（v1.2）

> 2026-11-27。适用范围：RZ/G3L。本文是 `plan/MCP_Rebuild_Plan.md` 的补充，对应"PoC 流程"之前的一步：由 agent 提出值得做的 PoC 构想，用户挑选后进入现有的 `poc_create` 流程。
> 主会话负责拆解、评审和验收；每个工作包由一个独立会话实现。

## 0. 摘要

- **目标**：用户发起一次构想，得到 8–10 个排好序的 PoC 提案。每个提案都有需求证据、可行性核对结果和分数构成，用户只需要挑。
- **核心判断**：直接让模型"想几个好点子"只会得到泛泛之谈。质量来自三样东西：有出处的输入信号、硬性的可行性筛选、明确的评分表。
- **做法**：一条七步流水线（第 3 节）。服务器只增加一个只读工具，联网调研由 agent 自己完成。
- **先验证再开发**：先用纯提示词把流程手工跑一遍，和"直接让模型想"盲评对比（I0）。流程确实更好，才做工具。

## 0B. 第二轮检验后的修订（v1.2，2026-11-27）

I5 已完成，结果见 `eval/poc_ideation_trial/results.md` 第 7 节。**本节优先于 0A 节和后文。**

- **0A 节的三条标准没有通过检验**：按它们预测用户对 10 个新提案的评价，只对了 3 个（标准是 8 个）。
- **0A 节里仍然有效的**：不做流水线；不打数字分；目标市场和产品线分工作为门槛；内部需求信号作为输入；可行性核对；提案模板的"对比对象"和"谁已经做过类似的"两栏。
- **0A 节里作废的**："三条标准"不再用于排序或筛选，提案不标"满足 / 部分 / 不满足"。

### 工具的定位

**多出候选，把事实查清，交给人选。** 工具不判断哪个提案好。

依据：三种做法的"值得做"比例都在四成左右（8 个里 3 个、8 个里 4 个、10 个里 4 个）。出 10 个提案大约得到 4 个可用的，这个产出已经有价值；而试图预测用户会选哪 4 个，两轮都失败了。

### `poc_ideate` 返回什么

1. 目标市场和产品线分工（用户维护）。
2. 内部需求信号（用户提供的工单高频主题）。
3. G3L 能力清单，每条带出处。
4. 过去的 PoC 列表。
5. **用户评过的提案**（新增）：两轮共 26 个提案连同评价，原样作为参考例子。以后每次用户评价的结果都追加进去。
6. 提案模板和门槛（0A 节的五条门槛）。

agent 据此直接构想约 10 个提案，逐个做可行性核对（查不到的标"未确认"），不排序，交给用户。

## 0A. 对照试验后的修订（v1.1，2026-11-27）

I0 已完成，结果见 `eval/poc_ideation_trial/results.md`。三条结论改变了本设计，**以本节为准，后文与本节冲突的部分作废**：

1. **不做七步流水线（第 3 节作废）。** 流程组 8 个提案里 4 个"值得做"，直接构想组 3 个，没有实质差别；两组有 5 个主题重合。
2. **原评分表作废（第 4 节作废）。** 它的排序和用户的评价相反：得分最低的三个全是"值得做"，第 2 和第 5 名是"不值得"。
3. **"演示效果抢眼"不是决定因素。** 用户实际按下面的标准评价。

### 修订后的做法

`poc_ideate` 仍是一个只读工具，但它不再规定流水线，只把直接构想缺的东西补齐。它返回：

- **目标市场和产品线分工**（用户维护）：
  - G3L 面向 HMI 这类带显示的应用，例如零售和 POS 终端、医疗和工业操作面板、楼宇和家居面板、充电桩，以及 IoT 边缘设备。
  - 不归 G3L 的：电机控制和工业实时网络有专门的产品线（RZ/T、RZ/N 系列），所以电机驱动、TSN 实时网关这类提案不提。
  - 双核的讲法：Cortex-A55 + Cortex-M33 的组合是 G3L 相对 MCU 产品（RA 系列等）的差距所在，是有效卖点。但要落在 HMI 设备上讲（例如"界面死机时关键显示不受影响""待机时由 M33 维持显示"），不要落到电机控制上。
- **内部需求信号**（用户提供）：近期工单里反复出现的主题。只需要主题和大致频次，不需要工单内容。已知的一条：安全相关（安全启动、升级、合规）的提问近期很多。
- **G3L 能力清单**（I1）和**过去 PoC 的列表**。
- **提案模板**（第 2 节，去掉"分数"和"反方意见"两个字段，加两个字段："谁已经做过类似的"，以及"对比对象"（客户不用 G3L 的话会用什么：MCU、竞品 MPU，还是 Renesas 的其他产品线））。
- **门槛和标准**（见下）。

agent 拿到这些后直接构想 8–10 个提案，对每个做可行性核对，然后交给用户选。

### 门槛（不过就不提）

1. 属于上面界定的目标市场，且不落在其他产品线的范围里。
2. 需要的驱动在当前 BSP 里有据可查；查不到的要明确标出"未确认"。
3. 硬件只用 EVK、现有转接板和可买到的现成模块。
4. 工作量不超过约 1 个月。
5. 不和过去的 PoC 重复。

### 标准（每条标"满足 / 部分 / 不满足"并写一句理由，不打数字分）

1. **对应一个真实的产品形态**：客户一眼能对应到自己要做的设备。
2. **有明确的市场或法规推动**：有竞品在做、有法规期限、近期工单里反复被问到，或有其他明确的需求出处。
3. **突出 G3L 的卖点**：低功耗待机、快速启动、双核、图形和视频编解码、没有 AI 加速器也够用等。

三条都"满足"的排在前面。演示效果只在其他条件相当时作为加分。

## 1. 用户已定的方向（2026-11-27）

| 事项 | 决定 |
|---|---|
| 给谁看 | 客户、内部销售和 FAE、展会和市场宣传，三者都要 |
| 什么算"好" | 试验前定的是"演示效果抢眼最重要"；试验后改为 0A 节的三条标准 |

| 应用领域 | 工业 HMI 和显示、工业网关和联网、边缘 AI 和视觉；同时允许流程自己发现其他领域 |
| 内部信号 | 工单和客户询价可以用，先去掉客户名和人名 |

## 2. 提案长什么样

每个提案一页，固定字段：

| 字段 | 内容 |
|---|---|
| 名称和一句话 | 30 秒内能讲清楚的说法 |
| 演示场景 | 观众看到什么、能动手做什么 |
| 需求证据 | 至少一条，带链接或出处（竞品演示、行业动向、去掉客户名的工单或询价需求） |
| 用到的 G3L 能力 | 具体的接口、外设或特性，带文档出处（文档编号、版本、页码） |
| 可行性核对 | 需要的驱动在当前 BSP 里是否支持（引用驱动手册）；需要的硬件清单，标明"已有"或"需另购（型号、大致价格）" |
| 工作量估计 | 按周估，列出主要工作项和最大的风险 |
| 最适合的受众 | 客户、销售和 FAE、展会三者里最适合哪个，为什么 |
| 分数 | 各项得分和理由（第 4 节） |
| 反方意见 | 第 3 节第 6 步的结论 |

## 3. 流程

1. **读能力清单。** G3L 有哪些接口和外设、BSP 里哪些驱动已支持、手边有哪些转接板。来自已索引的文档，每一条带出处。
2. **收集需求信号。**
   - 外部（agent 联网查）：竞品同档芯片的官方演示和参考设计、三个重点领域的行业动向。每条信号记下链接和日期。
   - 内部（用户提供）：工单和询价里反复出现的需求，去掉客户名。
3. **交叉生成候选。** 每个候选必须同时指向一条需求信号和 G3L 的一项具体能力。只有一边的不算候选。先多生成（20 个以上），再筛。
4. **可行性筛选（硬门槛，不过就淘汰并写明原因）。**
   - 需要的驱动在当前 BSP 的驱动手册里有。
   - 硬件只用 EVK、现有转接板和可买到的现成模块。
   - 估计工作量不超过 1 个月。
   - 不和过去做过的 PoC 重复。
5. **打分排序。** 按第 4 节的评分表。
6. **反方审查。** 对排名靠前的提案逐个回答：谁已经做过同样的演示？它和竞品的演示比有什么不同？销售真的会拿它给客户看吗？答不上来的降级。
7. **交给用户选。** 输出 8–10 个提案：三个重点领域各至少 2 个，另留最多 2 个给流程自己发现的领域。同时列出被淘汰的候选和原因。

用户选中的提案作为 `poc_create` 的设计起点。

## 4. 评分表

通过第 3 节第 4 步门槛的候选才打分。满分 100。

| 项目 | 权重 | 怎么打分 |
|---|---|---|
| 演示效果 | 35 | 见下面的四条，每条满足得一部分分 |
| 需求证据 | 20 | 证据的数量和质量：多个独立来源、有近期的、有内部需求的得高分 |
| G3L 的差异点 | 20 | 演示突出的是 G3L 相对同档竞品的长处，而不是任何板子都能做的事 |
| 复用面 | 15 | 能给多少类客户或场合用；做出来的软件能否成为后续 PoC 的基础 |
| 工作量和风险 | 10 | 越短、越确定，分越高 |

"演示效果"用四条可以核对的标准来打，避免凭感觉：

1. 不用讲解，30 秒内看得懂它在做什么。
2. 有看得见的输出或可以动手的交互（屏幕、动作、实时数据），不是只有终端日志。
3. 能独立摆在一张桌子上运行，不依赖现场网络或外部服务器。
4. 有一个让人记住的点：同档竞品没展示过，或者明显做得更好。

权重是按"演示效果最重要"定的初值。I0 的盲评和回测如果显示排序和用户的判断不一致，就调权重。

## 5. 放在哪里实现

沿用改造计划的原则：能力做成 MCP 工具，不靠斜杠命令。

- **新增一个只读工具（暂名 `poc_ideate`）。** 返回：流程说明、评分表、提案模板、G3L 能力清单、过去 PoC 的列表。它不联网、不生成构想，只把 agent 需要的规则和事实一次给齐。
- **能力清单是一份随仓库维护的文件**，由 agent 从文档索引整理、用户审过一次，文档或 BSP 版本变了再更新。不在每次构想时现查，这样每次的出发点一致，也省时间。
- **联网调研用 agent 自己的搜索能力。** 服务器不做爬取。
- **`poc_create` 增加一个可选输入**：选中的提案文件，写进新 PoC 的设计文档作为起点。

## 7. 风险和待定

- **回测样本少。** 目前已知的过去 PoC 只有 evk-mac 一个。请用户补充做过或被要求做过的 PoC 列表，哪怕只有标题和一句话。
- **边缘 AI 是否可行取决于 G3L 的实际能力。** 由能力清单和可行性门槛决定，不预设结论。
- **竞品信息有时效。** 每条外部信号记日期；超过一年的只作参考，不计入"需求证据"的高分。
- **内部信号的脱敏由谁做。** 建议用户提供前自己去掉客户名；流程里不处理带客户名的原文。
